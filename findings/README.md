# 结论

这里每篇是一个**可以被反驳的判断**，不是资料整理。案例、方案、数据都在仓库里，但它们只是证据。

四篇，按我写的时候觉得最站的住到最不站的住排：

1. [「提效 35%」不是测量结果，是一份不想被复算的声明](01-claims-are-not-measurements.md) — 缺口径不是疏漏，是理性选择；顺带承认我这套证据分级自己有漏洞。
2. [厂商测动作，独立研究测产出，所以差 80 倍不奇怪](02-action-vs-output.md) — 一个能带走的框架：先问测的是动作还是产出。
3. [FDE 是毛利结构，不是交付模式](03-fde-is-a-margin-structure.md) — 推翻我自己上一版写的「FDE 已成标准形态」。
4. [按结果收费的 AI，裁判和收款方是同一个人](04-who-defines-resolved.md) — 谈这类合同，第一件事不是谈单价。

每篇末尾都写了三样东西：这条判断**基于什么**、**哪里可能错**、以及**什么观察结果会让我作废它**。第三样最重要。一个不能被推翻的结论，和一句"赋能"没区别。

第 3 篇是直接改掉本库 `fde/README.md` 里的一句旧结论。结论被证据推翻就改，不另写文章打圆场。

**关于数据**：[`data/claims.csv`](../data/claims.csv) 是 73 条宣称的扁平记录，由 [`scripts/export_claims.py`](../scripts/export_claims.py) 从案例生成，判定规则写在代码里，可以质疑也可以改。我数了两遍得到两个不同的结果（42 和 47），差别全在"什么叫没有基线"——这件事写在第 1 篇里，没被当成误差抹掉。

数据不是产品。它能让别人把上面的结论重算一遍，仅此而已。
